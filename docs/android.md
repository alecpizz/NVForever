# Building the experimental Android app

The Android work is tracked by [issue #2436](https://github.com/LootJunkieAzza/NVForever/issues/2436).
It is not a qualified release yet. See [the design and acceptance gaps](design/android.md).

Install Rust stable, Python 3.11+, JDK 17, Gradle 8.11.1, Android SDK platform 35/build tools,
and Android NDK r28c. Set `ANDROID_HOME` and `ANDROID_NDK_HOME` to their installed directories,
and `JAVA_HOME` to JDK 17. On Windows the NDK's `windows-x86_64` toolchain is used.

```sh
rustup target add aarch64-linux-android
python tools/android/build.py --check
python tools/android/build.py
```

`--jobs 2` is the default. `--target-dir PATH` selects an independent Rust build cache;
`--gradle PATH` selects a Gradle executable; `--gradle-build-dir PATH` keeps Gradle output
and its project cache outside the source tree, useful on hosts protecting Documents.
The build uses a separate `android-dev` profile. It leaves release profiles unchanged.
The helper recreates Gradle app packaging outputs to avoid retaining obsolete native
payloads inside incrementally updated APKs; it preserves the Rust target cache.
The final command prints the debug APK path. This is a development signing key, not
an official release signature. A release distribution needs its own protected signing
configuration and device qualification.

The Android port has no LAN log uploader, pairing flow, or background test-report
queue in either APK variant. Native crash and event logs stay on the device for
manual collection. Android does not prompt for or send player reports.

Android launcher icons derive from the canonical NVForever artwork. To regenerate
them, run `java -Djava.awt.headless=true tools/android/LauncherIcons.java` from the
repository root; `--check` checks the tracked pixels without rewriting them.
Legacy density variants, adaptive foreground/background and Android 13 monochrome
resources share the existing brand. Physical launcher appearance remains to be checked.

The helper stages only Git-tracked JSON/YAML/TOML in this repository's schemas and lang
folders. Do not add game files. Install the generated APK using Android's package installer
or `adb install -r <apk>`, then use **Import game folder**. Select a folder copied from your
own lawful game installation. The importer needs enough space for the full Data directory
and leaves source files untouched. No game assets are downloaded or included in the APK.

The touch launcher uses the desktop launcher's news feed, release countdown, save selection
(with a compact last-save preview card showing thumbnail, character name, level, location and
playtime beside Play/Continue, plus the app icon in the top-left header),
settings catalogue and new-game start fields. Home, Settings, Mods and Game folder work in
portrait or landscape inside the system insets. Play requires a complete imported game;
Continue additionally requires an NVForever save. Settings writes only edited INI keys and
never writes the engine's settings catalogue: a normal player launch publishes it, including
the Mobile tab. Practice and layout customization still open in the game. The Android
launcher does not offer DLSS, desktop window controls or the desktop self-updater.
Project news is a separate HTTPS fetch and can be turned off on Home. An upgrade
still requires the same signer as the installed APK.

Developer checks without game data:

```sh
cargo test -p nvf-launcher --no-default-features --features mobile --lib --locked mobile::tests
python -m unittest discover -s tools/android/tests
javac -d <temporary-output> android/app/src/main/java/org/nvforever/android/InstallConfig.java android/app/src/test/java/org/nvforever/android/InstallConfigTest.java
java -cp <temporary-output> org.nvforever.android.InstallConfigTest
java -cp <temporary-output> org.nvforever.android.CountdownFormatTest
```

The existing desktop checks in CONTRIBUTING.md still apply to engine changes. A passing
cross-check or Java compilation does not replace desktop regressions or device acceptance.

The `android-test-apk` workflow cross-checks engine/input test source and runs the mobile
launcher tests on the host. It builds a signed debug APK and an unsigned release variant
using the same development native libraries. CI checks both APKs for the cleartext
policy, absence of the LAN uploader, ARM64 binaries and runtime content. The debug
signature and launcher JNI entry point are checked separately. These checks do not run
Android gameplay or input on a device. CI debug signing keys are temporary; an APK from another run may require an
uninstall, which deletes app saves. Keep your own development signing key for updates
and export saves before replacing an installation signed by a different key.

APK assets include the GPL licence, legal notice, exact source revision/link, third-party
Rust licence texts generated by the desktop release-notice tool, and the matching NDK's
notices for the bundled libc++ runtime. `merge*Assets` regenerates these notices for
binary packaging; Java-only checks do not need to package game files or load the game.

## Touch controls and layout editor

The movement stick is visible: drag with one thumb to move, and swipe empty space
with the other thumb to look. Action buttons use original geometric icons; held
buttons light up. The layout editor's Hints action controls action names and the
movement guide.

Open **Pause > Settings > Mobile > Customize layout** for the touch editor.
**Controls help / gesture practice** opens the isolated teaching screen. The compact editor
toolbar docks at the top or bottom edge (`Dock bottom` / `Dock top`), can be collapsed via
`Hide tools` / `Show tools`, and automatically hides while you drag any control so the
center of the screen stays unobstructed for placement. Drag a
control to reposition it, then use Smaller/Larger, Opacity and Show/Hide. Mirror
swaps the layout between hands; Stick mode chooses fixed or floating movement.
Game/Menu switches which group you edit. Settings and help have no persistent HUD shortcuts.
Reset restores that handedness layout; Cancel restores the layout before editing.
Save writes `touch-controls.json` in the app's own engine home, then leaves the game
paused on the same Settings page so you can resume deliberately. Cancel and Escape
return there with the original layout. It does not change keyboard bindings or saves.
The icon/editor revision still needs rendered device validation.

### Touch aiming follow-up

The editor's Aiming entry opens a bottom sheet. Look and ADS have separate minus/plus
adjustments. ADS means the engine's actual sight state, so holding aim during a reload
or blocking with a melee weapon does not use the ADS multiplier. These scales affect
touch-look swipes; external mouse and controller sensitivities stay in their existing
settings. Dead zone cycles through 10%, 18%, 25% and 35% of joystick radius on each axis.
Aim can hold or toggle. Sneak can toggle or act only while held, preserving independent
keyboard/controller toggle state when the touch hold ends. Reset aiming leaves button
positions alone; Save/Cancel includes both the layout and aiming settings.

These results apply to R9 source `28d5469`; later integration changes need their own
execution evidence. Rendered device validation remains separate.
An additional source increment adds **Adaptive touch actions** in the Touch settings
group. The existing Aim action displays **Block** for ready drawn melee weapons or
fists, and **Scope** for a ready drawn scope-equipped gun. Turn it off to keep the
static Aim caption and icon. Its action binding, saved `Aim` layout key, node and
position remain the same. The same R9 CPU run passed ten presentation/routing tests
and two preference tests, including held/toggled contacts, controller handoff and

## Mobile performance

**Mobile > Mobile performance** offers
Battery (30 FPS, 50% world resolution), Balanced
(60 FPS, 67%) and Quality (60 FPS, native). The frame limit and world resolution
can also be selected separately. Smaller world resolutions require FSR support;
unsupported choices explain why they are unavailable. Menus stay at display resolution.

Automatic thermal adjustment starts off. When enabled, warming temporarily limits
frames to 45 or 30 FPS and may lower an already-selected FSR resolution. Native
rendering stays native. The status row shows the effective limit and world resolution.
Settings recover gradually after sustained cooling; your latest choices remain saved.
Unavailable thermal feedback uses manual settings. Performance varies by phone and scene.

## In-game settings by touch

The in-game Settings menu keeps the exact desktop layout, typography, right-side rail,
scrollbar and proportions by default (`settings-menu-scale-v1` defaults to 100% under
**Mobile > Interface size** and takes effect immediately). Tap a tab, category heading or
row to activate it. Drag the settings list or scrollbar to browse without changing values.
Drag a slider sideways on its meter; a vertical drag there still scrolls the list. Drag
within an open choice list to see more choices, tap one to apply it, or tap outside to
dismiss the list.

## Optional touch views and appearance

Pause > Settings > Mobile keeps controls under topic headings. Enhanced terminal
and companion views have separate saved switches; turning one off keeps the
ordinary touch/menu and controller routes available. Controls help / gesture
practice explains the selected movement thumb, dead zone, walking/running and
fixed or floating joystick without using ammo or sending game actions.

Mobile > Dialogue offers Normal (default), Classic, Field Notes, Retro Console
and Wrist Terminal. Classic resizes cleanly to fill the mobile screen and safe-area insets
without black borders (keeping hardware corners and buttons uniformly scaled while expanding
straight metal bars and openings), and both Classic and
Wrist Terminal start with compact default text sizes that still scale with the dialogue text
sliders. Its TRADE button opens the normal barter menu when a merchant is
available. The installation can override the frame with
`Textures/Interface/NVForever/Dialogue/classic.png`.
Retro Console and Wrist Terminal use the installed Terminal and Pip-Boy models
with separate dialogue screens; Wrist Terminal uses an enlarged side panel (64% width and
full safe height) and frames the player's worn Pip-Boy screen tightly
for extra text room and makes its power button a tappable quick-exit whenever a normal goodbye
option is available (disabled during forced quest dialogue). A character without a worn
Pip-Boy (`[design]`, such as a new character before receiving one) talks on Normal. If a
model or template cannot safely present the
conversation, Normal keeps dialogue playable, touch-scrollable and exitable with
the on-screen controls still available, without changing the saved theme.
Minimal, Classic Glass and Split Panel still load as Normal, Classic and Field
Notes, respectively.

Original AI-generated artwork created by the PR author using ChatGPT image generation
for NVForever's Classic dialogue frame; not extracted or derived from *Fallout: New Vegas*,
Bethesda assets, or any third-party mod. Contributed by the author under the repository's
`GPL-3.0-or-later` licence (carrying no upstream third-party copyright/licence restrictions).

Field Notes uses the speaker-side and backing/accent settings. Retro Console and
Wrist Terminal place their model on the half opposite the chosen speaker side
(the whole safe area in portrait, with Standard, or when the side is too small to
read); the real device and Classic surfaces keep their own palettes. Mobile >
Dialogue's choice and subtitle text sliders size the text in every style; on phones
100% is a smaller base (85% choices by default) and rows stay at least 48 units.
Confirmation remains separate. Show dialogue hints and Show lockpicking hints
hide explanatory captions without disabling the interaction.

Opening an in-game text field (the character name, the settings search and forms,
the console when open) shows the phone keyboard; a tap while the field is open shows
it again after it was put away. Typed text, Backspace and Enter go to the field as before, and
the keyboard hides on Done, confirm, cancel or when the game loses focus. Desktop
and a physical keyboard are unchanged. The auto-move target above the stick shows

Mobile > Inventory and quick access offers optional left/right downward dismissal,
an explicit Close control and touch use of the physical model wheel. Hiding
