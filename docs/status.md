# NVForever status map

What is built, what is partly built and what is not started, per system. Built from the
design and spec notes, [owner-review.md](owner-review.md), the script stubs audit
([design/script-stubs.md](design/script-stubs.md)), the script function coverage table
([design/script-function-coverage.md](design/script-function-coverage.md)) and the merged PR
titles; written whole on 2026-10-25 (up to #799, with the ESM audit
[esm-audit-2026-10-25](handoff/esm-audit-2026-10-25.md)), and since then each row is edited
by the pull request that changes its system, so a row is as current as its system's last
change (the header carries no running counts, #2005). It states the project's own state,
not facts about the original game (those are tagged in the linked notes). Update the row
when a PR changes a system's state. What is left to do is in this map's Partly and Not started rows and in the open
issues; [outstanding.md](outstanding.md) is a snapshot of 2026-10-25, not kept up.

- **Done**: built and checked (parity lab, smoke scenario or in-game capture), open points
  are small.
- **Partly**: the core is built; the gaps are named.
- **Not started**: nothing of it is built (script functions that need it are stubs).
- **Awaiting owner**: built with guessed values or a design choice the owner has to confirm;
  the open gameplay decisions are in [owner-review.md](owner-review.md), the guesses the
  original game can settle in [observer-checks](handoff/observer-checks.md) and
  [its folder](handoff/observer-checks/README.md), and every guess is still in its spec note.

Checks referred to below: the parity lab (`parity-lab/`, scenarios per layer `L1`–`L5`,
compared with independent readers and in-game captures) and the smoke runner
(`tools/smoke`, the scenarios in `tools/smoke/scenarios.toml`; `python tools/smoke verify`
counts them). Which runs checked a change, and on which commit, is in its pull request,
not here.
