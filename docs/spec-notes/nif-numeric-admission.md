# Finite NIF mesh and skin input admission (Android-only)

[documented: `fnv-nif` codec/scene views and the asset consumers in `nif_spawn.rs`, `actor.rs`, and `model.rs`] The decoder retains floating-point data from the file. This note defines an **Android-only** (`#[cfg(target_os = "android")]`) engineering admission rule for mesh streams sent to Bevy and the GPU. Desktop builds (`#[cfg(not(target_os = "android"))]`) keep the existing `main` mesh/skin admission path unchanged without rejecting shapes for non-finite values. This note does not describe how the original game handles malformed files, and does not change the raw format decoder.

[documented: the earlier public [skin-weight path at 26e5fc780](https://github.com/LootJunkieAzza/NVForever/blob/26e5fc7805a9dc563ba740401aecef7479a6604c/engine/nvf-assets/src/nif_spawn.rs)] The previous path selected four weights, summed them as `f32`, and normalized them without a finite-input check. A missing or unusable skin returned `None`, which callers could draw as an unskinned mesh. Numeric refusal needs a separate error result so malformed declared skin cannot silently take that fallback.

## Admission policy

[hypothesis: NVForever engineering policy] Reject the rendered shape if an uploaded position, cardinality-accepted normal or first UV set, active in-range influence, normalized weight, inverse-bind matrix, or final generated vertex stream is nonfinite. Do not discard individual vertices, triangles or influences to repair a numeric failure. Existing out-of-range triangle filtering and mismatched optional-stream behavior remain. There is no arbitrary finite-magnitude threshold or bounds clamp.

[hypothesis: NVForever engineering policy] Validate a declared skin even for a prepared model's static bind-pose copy. Keep absence separate from malformed numeric skin. Each of the three consumers uses the shared admission result before publishing the shape's mesh, material or bind handles; a rejected shape contributes no bounds. Valid neighboring shapes remain eligible.

[hypothesis: NVForever engineering policy] Keep descending total ordering, stable ties, the top four joint indices, and the existing fallback when the selected sum is nonpositive. Use compensated `f64` accumulation and division for finite selected weights, then require finite `f32` results. Two `f32::MAX` weights become 0.5/0.5. Finite signed weights remain supported: `[2,-1]` remains `[2,-1]`. Positive/negative zero, nonpositive sums and unweighted vertices retain `[1,+0,+0,+0]`. Out-of-range vertex influences retain their existing ignored-input behavior. Reject unrepresentable normalized results after near cancellation. Ordinary finite results can differ in their final rounding bit from `f32` accumulation; no bitwise identity or native nonnegative-weight rule is claimed.

[documented: existing `fix_vertex_colors`, `build_mesh`, and `docs/spec-notes/nif.md` vertex-color policy] Preserve intentional vertex-color repair. Validate the final color stream after that repair. Stored file tangents are not imported by `build_mesh`; validate the tangent data actually generated for the mesh before publication. Missing normals retain Bevy's existing generation and finite zero fallback for degenerate geometry.

[hypothesis: NVForever engineering policy] Keep at most eight `(block, reason, element)` rejection samples per file preparation, saturate the additional-shape count, and emit one bounded summary. Bound the source label to 240 characters. Do not keep an unbounded name set or log every vertex. Texture cache allocations made during material preparation retain their existing cache ownership.

## Qualification and limits

[implementation evidence: authored CPU controls in `engine/nvf-assets/src/nif_numeric_admission_tests.rs`] The 17 new tests pass individually and as part of the full 172-test asset library suite, with no failures or ignored tests. The 155 existing tests remain. These controls exercise the shared admission helper, material/color preparation and actual Bevy mesh/bind/bounds behavior using authored structures, without game files. The source files remained unchanged during execution. Compilation and discovery are recorded separately from test execution.

[hypothesis: remaining qualification] A supported same-oracle baseline/candidate behavioral comparison remains unrun. No compile failure, missing selector or static source comparison is counted as a behavioral baseline failure. The CPU controls do not execute whole-file loading through all three consumers, a graphics driver, or a phone. They do not identify the cause of the reported crash, gray actors or historical device loss.

[documented: existing node transforms, animation/morph, material and particle paths] This is not a complete finite-transform or finite-shader boundary. Node and accumulated world transforms, later animation or morph edits, material uniforms, particle geometry, signed-weight culling and joint-reference semantics remain separate. Existing skeleton checks and fixed/bind bounds calculations remain. Finite uploaded data alone cannot guarantee finite downstream products at arbitrary magnitudes. No new bone-count policy is introduced.
